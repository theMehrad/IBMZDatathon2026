The Debugging Table · IBM Z Datathon 2026 · Oct 17 to 18

OutOfRole build plan

OutOfRole spots insiders while they are still active, explains each alert with checked evidence, and suggests which access each person should keep pre-approved. It all runs on one LinuxONE server, and people appear only as pseudonyms (U-017).

What we're building

HeadlineEarly warning

Replay the logs day by day. Compare each person with their own normal weeks; the 20 most unusual people form a daily review list.

ExplainGranite case files

Code picks the evidence ("new to this person, rarest first"). Granite writes the explanation citing it, and code checks every number before anyone sees it.

PreventLeast-privilege advisor

A recommender predicts which websites each person is likely to use next, so those can be pre-approved. Anything else goes to a reviewer; sites nobody here has visited are blocked.

"Most insider tools find the culprit after they've left. Ours put 80 of 99 insiders on a 20-name daily list while they were still active, twice as many as a standard 28-day baseline, and on average about half of each one's malicious actions came after the flag. Granite, on the same server, writes a case file citing the evidence. A recommender suggests which access to pre-approve, so reviewers see fewer routine requests."

Fixed detector settings
  • A feature is unusual when the last 7 days beat every one of that person's training weeks.
  • The running score halves every 7 days.
  • The list holds 20 names a day.
Recommender settings

Rank 64, alpha 0.5, regularization 1.0 on log(1 + active days), numpy version in recommender_als_simple.py. Spark's ALS scales regularization differently: if you use it, re-tune on the last training month and pick by how many next-month new sites it catches.

Demo (3 minutes)

  1. The replay plays. A leaker joins the daily list on the day of the first wikileaks upload.
  2. Click the person. Granite's case file streams in, and each number turns green once the code confirms it.
  3. Access panel: 20 pre-approved sites. A request for wikileaks.org is blocked as new to the company.

Say this, not that

Flags insiders while they are still activeReal-time production system
Suggests which access to pre-approveTrims access to what people need
The recommender predicts legitimate accessThe recommender detects insiders
  • As a detector, the recommender is no better than popularity; we tested it.
  • Say openly that two-day sysadmin sabotage is mostly missed, and that CERT is synthetic data.
  • Only 28% (r4.2) and 41% (r5.2) of the recommender's extra grants were later used, so it suggests; it does not decide.
  • Say plainly that the approach changed after testing. The abstract promised recommender-based detection; tests showed that own-history baselines detect better, so the recommender moved to access advice.
  • Compare against the strongest baseline. At similar list churn, the 28-day baseline flags 59 of 70 (a tie on r4.2) and 40 of 99 (half of ours on r5.2).
  • The early-warning method was picked after seeing results. The full detector we had named in advance also beat the baseline: 54 vs 28 of 99 r5.2 insiders flagged in time.
